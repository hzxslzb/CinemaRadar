# 01 · 项目目标与功能边界

## 1. 项目定位

CinemaRadar 是中国大陆影院排片查询与新场次订阅工具。核心需求是：用户关心某家影院的某部电影，希望影院新增场次后获知，并能快速进入票务平台继续选座。

系统处理的是“发现场次、比较变化、提示用户、跳转购票”链路；当前应用没有票务账户登录、座位图、锁座、收款、出票或退款业务。

源码入口为 [`main.dart`](../lib/main.dart)，功能入口由 [`app.dart`](../lib/app.dart) 提供，业务状态集中在 [`AppController`](../lib/app_controller.dart)。

## 2. 关键产品约束

### 2.1 每台设备独立运行

Android 和 macOS 各自请求外部数据、保存订阅、比较场次并发送本地通知。电脑不是手机的后端；手机不需要与电脑配对，也不通过局域网访问电脑。

由此产生的行为是：

- 设备 A 新增订阅，设备 B 不会自动出现该订阅。
- 设备 A 关闭、断网，不影响设备 B 独立使用。
- 应用没有集中推送服务；当前设备不运行且系统不调度后台任务时，无法由另一台服务器代为检测并推送。
- 更换设备、卸载或清除应用数据时，订阅没有内置云端恢复机制。

### 2.2 查询应有明确范围

影院目录按城市、行政区加载。排片只查询当前查看影院及已有订阅对应的影院，不循环扫描所有城市。

启动时有一个默认回归影院，即上海 MOViE MOViE 前滩店。这意味着首次启动会自动请求该默认影院，而不是等待用户首次打开搜索框才发起所有网络请求。

### 2.3 低开销与时效之间的取舍

前台间隔固定为 3 分钟。后台设置提供多种选择，但 Android 周期任务最低按 15 分钟处理。系统可延后执行任务，不能把选择的间隔当作精准通知时限。

同影院多部影片复用一份影院排片快照。系统监控的主要网络开销随“订阅涉及的不同影院数”增加，而不是简单随“订阅电影数”增加。

## 4. 三个平台的实际范围

| 维度 | Android | macOS | HarmonyOS |
| --- | --- | --- | --- |
| `1.0.3+4` 发布包 | APK | 双架构应用 ZIP | 本版不提供 |
| 前台刷新 | 3 分钟 | 3 分钟 | 保留源码中的 3 分钟逻辑 |
| 后台方式 | WorkManager | 应用进程内 Timer | 当前未实现后台轮询 |
| 自定义间隔 | 系统下限为 15 分钟 | 非前台且有订阅时使用所选间隔 | UI 隐藏该设置 |
| 关闭窗口后 | Activity/进程受 Android 管理 | 不主动结束应用进程 | 不承诺常驻 |
| 权限入口 | 通知、电池优化、应用详情 | 通知申请、登录项设置 | 通知申请、华为系统应用详情 |

macOS 的“关闭窗口继续运行”不等于系统服务：主动退出应用、关机、进程被结束和系统休眠都会影响检测。HarmonyOS 设置页跳转依赖已实现的华为系统组件路径，不是所有 OpenHarmony 系统的通用协议。

## 5. 用户流程

### 5.1 浏览并订阅

1. 启动应用，加载本机设置和订阅，查询默认影院。
2. 打开“切换影院”，搜索城市，选择行政区。
3. 在一次目录加载完成后，本地输入影院关键词。
4. 选中影院并确认切换，加载该影院影片与场次。
5. 选择影片，可按时间排序和影厅筛选。
6. 点击“订阅新场次”；已有场次成为基线，不会立即全部提醒。
7. 按提示授权通知或完善后台设置。

### 5.2 收到提醒

检测发现新的 `seqNo` 后，尝试发出本地系统通知，同时持久化顶部提醒批次。应用展示时可展开查看更多字段，或点击具体场次进入猫眼网页。

关闭顶部消息只清除该批提醒，不取消影片订阅，也不会撤销已经发出的系统通知。下一次检测发现新 ID 时会产生新批次。

### 5.3 管理订阅

从右上角图标打开侧边栏。点击条目切换到对应影院/影片；点击删除图标并确认后停止该影片订阅。删除最后一个订阅会取消 Android 唯一周期任务。

## 6. 数据和业务语义

- “实时”在本项目中实际为周期查询，不是 WebSocket、服务端事件或毫秒级推送。
- “新增”指当前场次 ID 不在上轮保存的 ID 集合中，不是影院官方的上架时间。
- “可购”由数据源返回状态映射，不保证点击时仍有座位。
- “全部城市”指接口当前返回的有效条目，不等于人工核验的全国行政区全集。
- “模糊搜索”是归一化后的子串匹配，不含错别字容错、编辑距离、语义模型或影院拼音自动生成。

## 7. 验证基准

历史在线回归以上海 MOViE MOViE 影城前滩店（城市 ID `10`、影院 ID `37534`）的《奥德赛》为目标。自动化测试使用固定响应样本，避免影片真实排期随日期变化导致测试随机失败。

当前时点不能从历史样本推断影院仍在排映同一影片。在线回归脚本的影片要求属于历史测试假设，应在使用时重新确认。
