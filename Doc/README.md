## 如何理解文档中的结论

文档采用以下约定，避免把目标或推测写成已实现功能：

| 标记 | 意义 |
| --- | --- |
| 当前实现 | 能在所链接的仓库源码中直接找到对应逻辑 |
| 实现限制 | 当前代码或平台能力导致的边界，不等于必然每次触发的故障 |
| 建议 / 扩展方案 | 尚未落地的设计，不应写入用户功能承诺 |
| 示例 | 为说明结构而构造，不代表接口当前在线响应或真实可售场次 |

接口章节描述的是客户端现有请求约定，不是猫眼或淘票票对第三方的正式服务承诺。测试通过只证明所覆盖的行为；不代表接口长期可用或系统一定准点执行后台任务。

## 文档维护约定

1. 修改功能时同步修改对应章节及第 16 章常量/API 表。
2. 源码链接优先指向文件和符号名，避免大量使用易漂移的行号。
3. 架构和流程图使用 Markdown 内的 Mermaid，随 Git 版本控制并由 GitHub 渲染。
4. 修改存储结构时更新 JSON 示例、版本迁移和兼容说明。
5. 任何新方案在代码、测试、原生验证完成前，保留“建议”标记。
6. 历史 CI 失败和修复要保留事实背景，不能据此推断最新主分支仍失败。
7. 本次文档补充不修改应用功能、不递增应用版本，也不覆盖已有 Release 资产。
