# 15 · 隐私、安全与数据边界

本章依据当前仓库实现描述数据流，不是外部平台隐私政策的替代。未来增加遥测、账户、同步或票务交易时必须重新核对。

## 1. 当前收集和保存什么

| 数据 | 当前用途 | 保存方式 |
| --- | --- | --- |
| 订阅影院与影片 | 检测新增并恢复导航上下文 | SharedPreferences JSON |
| 已见场次 ID | 与下轮响应比较 | 同上 |
| 创建与最近检查时间 | 订阅元数据 | 同上 |
| 最近一批新增详情 | 跨启动显示顶部提醒 | SharedPreferences JSON |
| 主题、间隔 | 本机偏好 | SharedPreferences bool/int |
| 城市/影院目录 | 搜索候选 | 进程内 Future 缓存 |
| 当前快照、筛选和选片 | 页面展示 | 主要是进程内状态 |

当前代码没有票务账号、手机号、密码、支付卡、支付凭据或订单数据库。

SharedPreferences 不是项目自建的加密保险库。应用遵从系统应用数据隔离，但没有额外加密这些偏好。订阅可能反映用户观影兴趣与常去地域，应按个人偏好数据谨慎处理。

## 2. 发往外部的请求

- 猫眼：城市、行政区、影院目录和影院排片请求，包含所选城市/区/影院 ID、请求日期和浏览器风格头。
- 海报域名：`Image.network` 加载接口返回的图片 URL。
- 票务入口：用户点击后交给系统浏览器或外部 App，后续登录、授权和支付由对应平台处理。

接口服务器通常能够观察请求 IP 和 HTTP 元数据。即使项目没有自建后端，也不能描述成“完全不联网”或“外部不知道任何查询行为”。

## 3. 随机设备标识

排片 Provider 的 `uuid` 为安全随机数生成的十六进制字符串，按 Dart isolate 生命周期复用，不读取真实硬件身份，也未写入项目的本地存储。

这降低了主动收集硬件标识的需要，但同一执行环境内的若干请求仍可能被此值关联。它不是对外部数据源匿名性的完整保证。

## 4. 无自建同步与平台备份

当前没有自建订阅上传服务、账户登录或跨设备同步，也没有业务遥测上报代码。Flutter 开发命令自身的工具遥测与应用业务遥测是不同范围。

系统备份、系统通知同步、用户截屏/导出或第三方票务平台的数据处理不由本项目完全控制。代码没有专门禁用所有平台备份，因此“只保存在本机”应理解为项目没有主动上传订阅，而不是对所有操作系统备份行为的绝对保证。

## 5. 删除与保留

- 删除订阅：删除订阅列表内对应记录，不自动清除旧提醒中的上下文。
- 关闭提醒：清除当前批次，不取消系统通知、不删除订阅。
- 重启：保留订阅、主题、间隔和未关闭批次。
- 卸载/清除应用数据：可能移除本地数据；是否被系统备份恢复取决于系统与安装方式。

当前没有独立“清空全部数据”“导出个人数据”或历史消息管理页面。

## 6. 仓库凭据边界

以下不应提交：

- Android release keystore、JKS、key.properties 和密码。
- Apple 私钥、证书私钥导出包、公证凭据。
- HarmonyOS p12/p7b、私有 `build-profile.local.json5`。
- GitHub token、`.env`、SDK 本机绝对路径和第三方票务签名密钥。

`.gitignore` 已包含常见敏感后缀与本机配置。忽略规则只能防止普通新增，无法修复已经进入 Git 历史的秘密；提交前仍需检查 diff。遇到已泄漏凭据，应首先撤销/轮换，再评估历史处理。

公开 `ohos/build-profile.json5` 应保持 `signingConfigs: []`。签名提取/合并脚本处理的私有配置只能留在本机或经过明确配置的 Secrets 中。

## 7. 安装包签名与供应链

当前 APK 用开发调试证书签名，macOS 用 ad-hoc 签名、未公证。SHA-256 用于判断下载文件是否与已发布资产一致，不等于 Apple 公证或企业安全审计。

依赖通过 `pubspec.lock` 固定；GitHub Actions 采用完整 action commit SHA，SDK 固定 commit 并检查 HEAD。工作流读取权限最小化，不将 checkout 凭据持久化到工作目录。

构建依赖仍需访问 GitCode、Pub 镜像和 Flutter 存储，不能称为完全离线可复现。若未来引入新安装脚本，应检查来源和实际行为。

## 8. 外部链接与输入

猫眼具体场次 URL 由固定 HTTPS 域名、固定路径和 Uri 参数编码构造。其他 App 入口也是代码内固定 scheme；应用没有提供任意脚本执行或用户输入 URL 执行器。

排片文本作为 Flutter Text 展示，不作为 HTML/JavaScript 执行。海报 URL 仍来自外部响应，未来可增加 HTTPS 和来源约束；当前代码没有显式图片域名白名单。

Android `<queries>` 允许查找外部 scheme，不等于声明本应用接收这些 scheme。当前没有应用自己可被外部任意 deep link 写入订阅的实现。

## 9. 日志、截图与问题反馈

在线回归脚本输出影院、影片和场次时间，不输出用户票务密码。提交问题时仍应脱敏个人订阅、系统通知栏内容、设备账号和本机路径。

不要为定位设置页故障直接上传签名配置；通常只需错误码、平台版本和脱敏的 Want/Intent 目标。

仓库内历史截图来自产品演示回归，不代表所有平台最新界面或当前实时排片；引用时保持说明。

## 10. 数据授权边界

项目使用网页排片接口的事实不等于获得其长期商业使用授权。研究和扩展应区分当前可请求的数据、平台正式开放的授权 API、以及支付/出票所需的可信业务能力。

不要将第三方票务密钥打包到 APK 或桌面二进制；混淆代码也无法把客户端私钥变成可靠的秘密存储。
